# T07 素材与维护流程

日期：2026-10-12。仅为原创合成档案的本机工程闭环，不表示真实语料准入、生产反馈渠道或公开 V1 已验收。

## 清单与固定快照

搜索结果、原文阅读的“加入素材”和关系证据面板的“关系与证据加入素材”，统一调用 `POST /api/materials`。浏览器 localStorage 键为 `story-archive-materials-v1`，只保存格式版本、快照、最多 500 字主题备注、显式段落 ID 与每项关系的 ID / 固定证据组。正文和来源不缓存到清单；页面打开、范围切换和导出时重新取数。清理浏览器数据会丢失清单，同源多页通过 storage 事件刷新，没有云同步。

- 第一项素材固定快照；不同快照的加入请求在界面拒绝。可以回到清单快照检索，或清空新建。移除最后一项时解除快照绑定、保留主题。
- 以同一快照的出现位置 ID 去重，相同文字不同出处不会合并。关系 ID 去重；显式选段与证据共用段落只计一次。
- 最多 50 个独立片段、50 项关系。额外关系上限用于防止大量关系共享同一组证据时无限增加清单记录。
- 关系加入时固定投影中第一个完整可用证据组，不优化或偷偷切换到较短组来挤入容量。整个组加入后超限则拒绝整个操作。
- 固定组失效时不会自动换成另一组，即使关系仍有其他完整证据。用户移除并重新添加才选择新的当前可用组。
- 存储损坏、禁用或配额不足有明确错误，不覆盖原清单。清空需要展开说明后点击确认。丢失快照时仍能移除素材或清空。

## 服务端核验与素材包

`POST /api/materials` 是无状态解析接口，不在服务端保存清单。JSON 请求包含：

```json
{
  "snapshot": "fixture-2026-10-10-v1",
  "scope_ids": ["opening"],
  "purpose": "display",
  "topic": "师徒关系素材",
  "passage_ids": ["passage:03"],
  "relationships": [{"id": "relation:mentor", "evidence_ids": ["passage:03", "passage:04"]}],
  "add": {"kind": "passage", "id": "passage:06"}
}
```

`add` 可省略，类型仅支持 `passage` / `relationship`。快照必填，不允许服务器默认替换；范围必须明确。服务端在一次 SQLite 读取中载入快照与当前撤下 / 用途约束，再同时满足请求用途和 `export` 用途，最后校验选段与精确证据组。

响应包含规范化 `selection`、`count`、`limit`、`valid`、错误 ID 和允许的 `preview`；只有全部有效时才提供 `package`、`markdown` 和内容指纹。失效关系不返回其残缺证据；独立显式选中的可用段落仍可作为单独素材查看。错误不区分隐藏、不存在与撤下的具体内部原因，不泄露隐藏正文或标题。

- 非法字段 / 长度 / 重复 JSON 键：400；超出完整片段或关系容量：409；快照缺失：404；数据库不可用：503。
- 原文、关系不可用：200 且 `valid=false`，`package` / `markdown` 为 null，页面标记需处理项。
- 请求体限制 64 KiB；仅接受同源、本机 Host 的 `application/json`，拒绝未声明长度、重复长度及 Transfer-Encoding。读取超时 5 秒。清单标识信息也有 64 Ki 字符的本地保护上限。

JSON 素材包包含格式版本、主题、语言、合成声明、快照、内容范围、导出用途及核验用途、明确选择、原文、关系方向 / 条件 / 完整组、相关人物 / 条目和来源记录。段落保留出现位置与 source_locator，仅保留包内的 next_ids。Markdown 表达同样的资料和相对档案定位链接，来源文本 / 备注按字面转义，不把任意正文当作 HTML。复制时附当前档案服务地址。

复制 / JSON / Markdown 下载前都会再次请求服务核验，不依赖之前预览。路由、范围或选中清单在请求期间变化时拒绝旧操作。原文“复制引用”也复用此解析流程，但不依赖清单是否损坏或本地存储是否可用。AI 取材用途同时要求 `external_ai` 和 `export`；素材包里的 export 不代表任意资料都可送到外部模型。

## 收录说明与私有反馈

“收录纠错”页展示当前可用快照、合成样本范围、真实来源待接入、已知缺口及更新摘要，不输出隐藏内容的数量。段落与关系面板可预填快照 / 稳定 ID。六类问题：文本错误、归属错误、分支问题、人物关系错误、内容缺漏、内容使用问题。

`POST /api/feedback` 接收 `request_id`（UUID）、`kind`、`snapshot`、`reference`、`description`（1–4000 字）及可选 `contact`（至多 200 字）。问题可以引用不可用记录，因此不要求引用仍可公开。提交不发布正文、不发邮件、不访问第三方。

收件箱在当前档案数据库同目录的 `feedback.sqlite3`，与快照库独立，文件以 0600 创建 / 收紧权限；默认路径位于 Git 忽略的 `data/local/`。提交使用事务写入，提交完成后才返回编号。相同 UUID / 相同内容重试幂等，UUID 内容冲突返回 409。持久化频控为整台本地服务每十分钟最多五条新反馈，重复重试不占额度，超过返回 429；重启不重置计数。存储失败返回 503，不显示成功。界面失败保留表单，成功清除说明和联系信息；草稿仅存页面内存，刷新页面会丢失。

没有读取反馈的 HTTP 路由，普通日志不包含请求体或联系信息。维护者通过本地命令实际受理：

```bash
python3 scripts/manage_feedback.py
python3 scripts/manage_feedback.py --include-contact
python3 scripts/manage_feedback.py --resolve <反馈编号>
python3 scripts/manage_feedback.py --inbox /path/to/feedback.sqlite3
```

默认读取省略联系信息；显式选项才显示。`--resolve` 标记已处理。收件箱尚未创建、路径错误或不可写时命令失败，不制造空的成功结果。未承诺处理时限，当前不具备公网部署所需的身份验证、反滥用及隐私治理流程。

## 后续边界

导出核验的是最后一次服务端读取状态，下载文件不会随之后的撤下自动更新。浏览器 localStorage 不提供跨标签页事务或多设备合并。服务仍在完整快照投影后处理请求，没有规模性能结论。下一步 T08 建立可移植 Skill 与只读连接，真实资料必须通过相应用途准入才能接入。
