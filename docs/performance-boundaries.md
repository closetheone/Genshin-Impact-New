## 查询期间撤下与权限收紧

[原始结果](evaluations/t09/live-restrictions.json) 包含 16 个通过的场景，各使用独立 300 段库和十个同时固定读事务的 HTTP 请求。12 个提交场景覆盖 DELETE/WAL × 撤下/权限收紧 × display/export/external_ai；另有两种日志模式、两种变更的 display 回滚场景。测试门闩暂停在读事务已读取快照和限制版本之后，连接与请求均为真实 SQLite / HTTP。

- 提交前，搜索可见 285 段。撤下两段后新请求可见 283 段；收紧来源对指定用途的权限后为 0。受限关系的两组证据均不可用，详情返回 404，旧搜索游标返回 409。
- 默认 DELETE 模式下，固定读事务使写提交等待；测试在 0.1 秒内确认提交未完成，释放读者后提交成功。此测试不代表无限等待承诺，连接仍有原有锁等待超时。
- WAL 模式下，旧请求仍暂停时写入已提交，新请求立即使用新限制；释放旧请求后，其正文、数量、统计、筛选项保持完整的提交前事务状态。后来的提交不会取消已固定旧事务的在途响应。
- 权限收紧后，另一用途的搜索仍为 200 且计数不变。回滚场景结果保持不变，旧游标及关系仍为 200。

四项新增回归连同既有测试共 81 项通过。Python 编译、样本契约、JavaScript 语法和 Git 差异检查通过。上述验证不表示能收回客户端已有副本，也不替代生产鉴权验收。

## 缓存未命中扫描优化（2026-10-13）

未命中路径原先分别执行说话人计数、连接节点匹配及普通节点匹配，并在拓扑读取时强制物化包含正文的可见段落表。现在先用规范化正文的三元片段倒排选取候选；候选不足或未知时才扫描全部可见正文。候选仍在同一读事务中经过 scope、用途、撤下、条目和说话人过滤，并由原有 `instr` 精确复核。全量扫描路径也只把 ID、位置、说话人和命中标记写入精简临时结果，SQLite 汇总后再按完整可见拓扑排列命中项。候选索引作为 query index version 2 在导入 / 显式维护时建立，旧版本由 `prepare_indexes()` 在写事务中升级；读请求不会隐式迁移。

## 高命中查询剖析与汇总优化（2026-10-13）

先完成耗时拆分，再评估 FTS5，最后按实测收益改动查询路径。证据分别见 [优化前剖析](evaluations/t09/search-plans-before-100k.json)、[优化后剖析与 FTS5 对比](evaluations/t09/search-plans-after-100k.json) 和 [未命中 HTTP 矩阵](evaluations/t09/search-flat-aggregate-100k.json)。剖析与微基准均为顺序执行，带 cProfile 开销；不等同于 HTTP P95，也未清空操作系统磁盘缓存。

十万长文本的首条高命中查询，优化前总耗时 1.1199 秒，其中精确匹配及分组 SQL 0.8338 秒、拓扑 SQL 0.2008 秒、Python 排序 0.0562 秒。优化后同类剖析为 0.9588 秒：首次筛选项计数 0.7726 秒、匹配 SQL 0.1127 秒、拓扑 SQL 0.0007 秒、排序 0.0443 秒。SQL 时间包含权限筛选、读取和汇总，不能解释成纯 `instr` 时间；各查询依次共享拓扑和筛选项缓存。

FTS5 实验使用同一批 10,011 段规范化文本，在独立内存库中比较直接扫描、现有三元倒排和 `trigram case_sensitive 1`。末尾高命中词匹配 9,983 段，FTS 候选仍为 9,983 段，候选加精确复核 0.0287 秒，直接扫描为 0.0276 秒；低命中词两种索引均筛到 100 段，精确复核约 0.0003–0.0004 秒。空查询、短于三个码点或含 NUL 的查询需要回退；引号必须转义，AND 模式按词分别构造条件，并精确复核剩余短词。实验还核对中文、NFKC 全角与组合字符、emoji、大小写、`%` / `_`。微基准不含权限、排序、取页和 HTTP，不直接与十万规模的接口时间比较。

没有将 FTS5 接入服务，也没有改变 `instr` 和 query index version 2。高命中查询本身就匹配 99,968 段，保留完整结果时，候选数不能低于真实命中数。本轮改为 SQL 直接汇总命中 ID / 位置，去掉全部可见段落的命中标记临时表与重复分组；筛选项复用已存在的、绑定可见范围及限制版本的缓存。检查连接可见性及位置时，从连接候选 ID 开始读取，避免稀疏连接触发整库遍历。可见拓扑排序、页面正文复核和游标语义不变。
