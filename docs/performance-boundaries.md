# T09 性能边界与查询期间限制验证

日期：2026-10-13。本文记录本地合成负载的适用范围，不代表真实原神资料、公开 V1 或生产环境验收。正式结果保存在 `docs/evaluations/t09/boundary-*.json` 和 `docs/evaluations/t09/live-restrictions.json`。

## 已完成的测量

测试使用 Apple M1、8 GiB 内存、Python 3.13.3、SQLite 3.49.2，在本机回环 HTTP 上运行。每个场景独立预热一次，再以十并发发送 30 次；延迟从客户端发起请求到完整响应体读取、JSON 解析和 oracle 校验结束。搜索与图谱的一秒要求来自 PRD；阅读和 AI 邻域只记录诊断值，没有擅自把一秒当成它们的产品承诺。深分页游标由可信测试程序预先签发，计时只测目标页响应，不包含走过之前页面的时间。

纯深分页（100,000 段、96 字、无额外连接）首屏搜索 P95 为 0.8987 秒，深搜索 P95 为 1.3014 秒；深处阅读 P95 为 11.0521 秒。它说明深游标签发本身不是主要成本，阅读目标定位仍需处理大范围顺序。20,000 段的长文本加连接组合负载也全部无错误：搜索高命中、低命中、零命中、深页 P95 分别为 10.7458、9.1332、1.4690、11.2397 秒，深处阅读为 16.2388 秒；图谱 0.2697 秒，AI 邻域 0.0605 秒。组合结果只代表 20,000 段的内存受控实验，不能外推成十万段验收。

## 查询期间撤下与权限收紧

`scripts/check_live_restrictions.py` 在独立 300 段库上使用真实 HTTP 和 SQLite 连接，覆盖 DELETE/WAL 两种日志模式、撤下/权限收紧、display/export/external_ai 三种用途，以及每种写入的 rollback，共 16 个场景。四项自动化测试先以三名并发读者完成同一断言。

验证结果：

- 每个请求在初始化时固定 snapshot、用途和限制版本；在途请求的正文、数量、游标和关系证据保持同一事务状态。
- 默认 DELETE 模式下，写提交等待固定读事务；释放读者后才完成提交。提交后新请求立即看见撤下或权限收紧，旧游标返回 409，受限关系返回 404。
- WAL 模式下，写提交不等待旧读事务；提交后的新请求使用新限制，旧读请求释放后仍完整返回提交前的旧事务结果。这个一致性语义不会取消已发出的响应。
- 权限收紧只影响指定用途；其他用途的计数和结果不变。回滚不改变结果，旧游标和关系仍可用。

这些检查证明了读事务的一致性和限制版本绑定，不能解释为对客户端已经持有的内容做即时撤回。

## 结论与下一项

本轮把性能声明收窄为：短独立段落的搜索和图谱基准达到一秒目标；长文本扩展负载的搜索、深分页阅读未达标，密集对白连接和组合负载以正式报告为准。下一项应优化长文本字面扫描、密集连接的拓扑排序及深处段落定位，并用同一合成 oracle 和权限并发矩阵复测。仍需在获准真实批次和目标部署环境中重新测量，合成结果不替代真实资料准入。
