# T09 性能边界与查询期间限制验证

日期：2026-10-13。结论：缓存未命中的正文扫描已合并，十万长文本首次高命中搜索从 12.3307 秒降至 1.2805 秒；八条查询轮换与撤下后重新查询的 P95 分别为 0.5247、0.7776 秒。十并发全新查询 P95 仍为 6.2215 秒，尚未通过一秒目标。以下全部使用原创合成文本，不代表真实资料、公开 V1 或生产环境验收。

## 方法与负载

环境为 Apple M1、8 GiB 内存、Python 3.13.3、SQLite 3.49.2。客户端与服务端共享一个 Python 进程，通过本机回环 HTTP 通信。四类负载顺序运行，各场景独立预热一次，再以十并发发送 30 次请求；延迟包括完整响应体读取、JSON 解析和 oracle 断言。P95 使用 nearest rank，即第 29 个排序值。未清空操作系统磁盘缓存，首次请求不代表冷磁盘读取。RSS 包含生成器及 oracle 的内存。

保留原样本 32 段，追加段落的长度如下；查询词位于正文末尾，测试高命中、低命中、零命中。带连接负载具有相邻逆序边、分支和汇合，每个节点最多向后连接第 1 和第 4 个拓扑节点；约十分之一追加段落在 opening 范围不可见，用于验证隐藏前驱后的排序。密集对白连接不等同于密集人物关系图，图谱仍为原基准的小型星图。

## 查询期间撤下与权限收紧

[原始结果](evaluations/t09/live-restrictions.json) 包含 16 个通过的场景，各使用独立 300 段库和十个同时固定读事务的 HTTP 请求。12 个提交场景覆盖 DELETE/WAL × 撤下/权限收紧 × display/export/external_ai；另有两种日志模式、两种变更的 display 回滚场景。测试门闩暂停在读事务已读取快照和限制版本之后，连接与请求均为真实 SQLite / HTTP。

- 提交前，搜索可见 285 段。撤下两段后新请求可见 283 段；收紧来源对指定用途的权限后为 0。受限关系的两组证据均不可用，详情返回 404，旧搜索游标返回 409。
- 默认 DELETE 模式下，固定读事务使写提交等待；测试在 0.1 秒内确认提交未完成，释放读者后提交成功。此测试不代表无限等待承诺，连接仍有原有锁等待超时。
- WAL 模式下，旧请求仍暂停时写入已提交，新请求立即使用新限制；释放旧请求后，其正文、数量、统计、筛选项保持完整的提交前事务状态。后来的提交不会取消已固定旧事务的在途响应。
- 权限收紧后，另一用途的搜索仍为 200 且计数不变。回滚场景结果保持不变，旧游标及关系仍为 200。

四项新增回归连同既有测试共 81 项通过。Python 编译、样本契约、JavaScript 语法和 Git 差异检查通过。上述验证不表示能收回客户端已有副本，也不替代生产鉴权验收。

## 缓存未命中扫描优化（2026-10-13）

未命中路径原先分别执行说话人计数、连接节点匹配及普通节点匹配，并在拓扑读取时强制物化包含正文的可见段落表。现在只扫描可见正文一次，将 ID、位置、说话人和命中标记写入精简临时结果；SQLite 汇总数量与命中标识后返回 Python，再按完整可见拓扑排列命中项。这样既避免长文本临时复制，也避免十并发时逐行转换十万条 SQLite 记录。拓扑查询不再强制物化全文；快照、scope、用途、撤下、人物依赖、字面匹配和游标语义保持不变，无需数据库迁移。

| --- | ---: | ---: |

| 低命中 | 8.9966 s | 0.4313 s |
| 零命中 | 1.3192 s | 0.4459 s |

新增 [缓存未命中矩阵](evaluations/t09/search-misses-optimized-100k.json) 使用同一十万段、追加段落为 1024 字的合成库。30 条全新查询按高 / 低 / 零命中各十条组成，以十并发发送；高命中词取正文开头的不同前缀，低命中词位于末尾。八条低命中查询顺序轮换，超过六条结果缓存容量；撤下场景每次先提交一个追加段落的撤下，再请求同一高命中查询。后两种场景各顺序执行 30 次，以保证淘汰及限制版本更新的因果顺序，不能当作十并发成绩。

测试包装现有缓存读取方法，只记录命中/未命中，不清空或扩容缓存；90 次计时请求均确认未命中、零错误。oracle 在计时外由完整投影和原排序算法生成，逐次核对正文、顺序、可见连接、总数、统计与筛选项。计时含 HTTP、完整响应体、JSON 解析与断言，不含数据准备和撤下写入。报告保存被测实现的 SHA-256；并发权限收紧仍由既有 DELETE/WAL 回归覆盖。
