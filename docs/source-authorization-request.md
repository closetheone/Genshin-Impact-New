# 真实来源授权记录模板

本模板用于记录来源方或有权代表人的明确确认。填写模板本身不构成授权，也不能把网页可访问、仓库开源许可证、robots 结果或站内编辑规则当成授权依据。

## 1. 来源与对象

- 来源名称与 `source_id`：
- 授权确认人及身份 / 组织：
- 确认日期与时区：
- 确认记录定位（邮件、工单、公开许可页或其他可复核链接）：
- 具体页面、仓库、数据集或字段范围：
- 版本、修订号或有效期间：
- 授权有效至（ISO `YYYY-MM-DD`，或明确填写 `no_expiry`）：
- 排除对象（例如图片、音频、游戏原文、用户投稿、品牌元素）：

## 2. 分项用途

请对每项用途填写 `allowed`、`limited` 或 `denied`，并写明条件。没有明确答复的项目保持 `unknown`，不能用整站许可或代码许可证补齐。

| 用途 | 状态 | 条件、范围和期限 |
| --- | --- | --- |
| `collect` 采集 |  |  |
| `store` 存储 |  |  |
| `display` 公开展示 |  |  |
| `export` 导出或下载 |  |  |
| `ai_retrieval` 项目内 AI 检索 |  |  |
| `external_ai` 发送给外部模型或服务 |  |  |

## 3. 技术与内容限制

- 是否允许 API、人工整理或授权导出：
- 访问频率、登录要求和缓存期限：
- 是否必须署名、保留来源链接或附带许可文本：
- 是否禁止批量抓取、镜像、网页快照或重新发布：
- 是否需要过滤未实装、解包、测试服、同人或用户投稿内容：
- 撤下、用途收紧、授权到期和纠错通知方式：

## 4. 入库前复核

只有在确认记录可定位、授权人和对象范围明确、每项请求用途都有 `allowed` 或符合 `limited` 条件后，才更新 `data/source-audit.json` 的准入字段。之后仍需完成来源定位、版本快照、人物映射、分支和关系证据核验；授权不等于正文完整或剧情真实性已经验收。
