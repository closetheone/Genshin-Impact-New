# 角色目录与资料接入

2026-10-15 更新：真实角色基础资料已通过独立目录扩充至 124 条社区记录，并匹配 120 个官网角色展示入口，详见 [真实角色接入记录](real-character-intake.md)。官网入口只保存导航元信息，立绘、简介和配音在官网查看。以下段落描述原有合成剧情角色流程，仍不接收真实故事或图像。

角色目录已接入本地原型的独立页面 `#/characters`，通过 `/api/characters?q=&limit=200` 读取当前快照中可见的人物记录。页面提供角色卡片、名称 / ID 搜索、资料状态筛选、稳定 ID、关系证据入口和后续资料字段的位置。点击卡片会进入 `#/character?id=...`，详情接口 `/api/character?id=...` 沿用同一组显式 `scope`、`purpose` 和固定 `snapshot` 边界。

角色详情只返回当前投影允许的角色、对白、关系、条目和来源。对白最多返回 50 段，关系最多返回 100 条；服务会先截断正文，再按截断后的记录收集条目和来源，避免把边界外的元数据带到页面。撤回记录、来源用途限制和缺失的关联证据都会使对应内容消失或让角色不可用。页面会显示当前范围、快照、关系描述、审核状态和可见证据组数量；达到上限时会明确提示。详情页的立绘位置目前仍是占位符，页面明确标注原创合成样本，不把样本内容当作原神角色资料。

当前仓库只有原创合成样本，因此卡片中的立绘、元素、武器、阵营、稀有度和角色故事不会伪造或填入原神内容。没有这些字段时，页面显示“立绘待授权”和待接入说明。

真实角色批次接入时，建议先从少量角色开始，逐项记录：

- 名称、别名和稳定角色 ID；
- 来源页面、修订标识、游戏版本和内容类型；
- 基本信息字段与角色故事的具体授权范围；
- 立绘文件的来源、署名、展示 / 导出限制和撤下方式；
- 能回到原文的故事段落和关系证据。

角色目录的出现不代表真实资料已经获准。真实角色页面开放前仍需通过 `scripts/check_release_readiness.py`，并完成正文数据契约与来源核验。详情中的关系入口会以当前角色为中心打开图谱，并预选对应关系，便于直接回到证据。
