# SQLite 索引读取链路

这轮 T09 优化把普通查询从“每次读取完整快照、校验并构造投影”改成导入时建立、请求时只读的 SQLite 索引链路。索引仍然服务于合成原型，不能替代真实资料准入或公开部署验收。

## 建立与发布

`query_index.py` 为每个快照建立四类数据：

- `query_records` 保存可检索字段、范围位图、顺序和关系端点；
- `query_links` 保存显式段落连接；
- `query_evidence` 保存关系证据组成员；
- `query_snapshots` 保存内容哈希、是否就绪和是否存在反向连接；`query_state` 保存索引版本与限制版本。

导入器在同一个写事务中更新来源限制、撤下集合和索引，最后才把快照标为就绪。服务启动时 `prepare_indexes()` 只补建缺失或过期索引。普通 HTTP 读请求不执行建表、写索引或自动修复；索引不可用时返回 503。

## 请求边界

`indexed_archive.py` 在只读事务中先固定快照、scope、purpose 和当前限制版本，再执行搜索、阅读、图谱、人物和关系读取。来源用途与撤下状态实时参与过滤，旧快照也会接受当前限制。游标包含快照内容哈希和限制版本，限制变化后旧游标返回过期错误。

正文阅读使用 `/api/read` 分页，每页最多 50 段。图谱先分页人物和关系标识，再补当前页的证据文本；没有完整证据组的关系不会出现在结果中。范围外、用途不允许或已撤下的内容不会因为定位或翻页自动扩大。

搜索将命中数与说话人统计合并在一次索引扫描中；每条 SQL 预计算可用来源、条目和人物，避免每个段落反复检查同一依赖。字面匹配仍使用规范化后的 `instr`，保持大小写、NFKC、空白处理和关键词 AND 语义，没有改用 FTS 或跨请求结果缓存。

含逆序连接的快照只对当前可见连接两端的节点进行拓扑排序。连接节点的排序键为其遍历过程中的最大原始位置与遍历序号；独立节点沿原始位置索引读取。分页只取独立节点的一小段，再与命中的连接节点合并，最后按当前页 ID 读取正文。不能先过滤关键词再对命中子图排序，否则可能改变对白顺序；也不能直接过滤全库的固定拓扑名次，否则撤下或范围变化后顺序可能错误。

若当前页偏移为 O、页大小为 L、命中的连接节点数为 M，独立序列从 `max(0, O-M)` 开始读取至多 `L+M` 项，合并后截取目标页。被省略的独立前缀必在目标页之前，因此深分页不会漏项或重复。AI 小邻域不超过 20 段时只按 ID 读取所需段落。`/api/view` 和素材包重新核验仍使用完整快照路径。

普通 SQL 修改正文或索引会通过触发器将索引标为未就绪；来源权限只允许收紧，撤下不可撤销。拥有移除触发器或直接改写数据库文件能力的管理员不在这个只读接口边界内，仍需使用维护校验和可信备份。重建前会完整校验原始快照；重建不能修复损坏的原始正文。

## 当前性能结论

2026-10-13 搜索专项优化后，十万段落十并发复测中，搜索 P95 为 0.5097 秒，图谱为 0.2788 秒，AI 段落为 0.0718 秒；搜索和图谱达到本机合成基准的 1 秒目标。原始数据见 `docs/evaluations/t09/benchmark-search-optimized-100k.json`，此前索引版结果继续保留。

文本仍需扫描，深分页仍需跳过独立序列前缀；如果绝大多数段落互有连接，连接节点集也可能很大。这次基准包含大量独立短段落和小型关系星图，不能替代真实长文本、密集对话、跨设备或生产网络验证。
