# SQLite 索引读取链路

这轮 T09 优化把普通查询从“每次读取完整快照、校验并构造投影”改成导入时建立、请求时只读的 SQLite 索引链路。索引仍然服务于合成原型，不能替代真实资料准入或公开部署验收。

## 建立与发布

`query_index.py` 为每个快照建立六类数据：

- `query_records` 保存可检索字段、范围位图、顺序和关系端点；
- `query_links` 保存显式段落连接；
- `query_evidence` 保存关系证据组成员；
- `query_grams` 保存规范化正文的候选三元片段频率；
- `query_postings` 保存低频片段到段落位置的倒排候选；
- `query_snapshots` 保存内容哈希、是否就绪和是否存在反向连接；`query_state` 保存索引版本与限制版本。

导入器在同一个写事务中更新来源限制、撤下集合和索引，最后才把快照标为就绪。服务启动时 `prepare_indexes()` 只补建缺失或过期索引。普通 HTTP 读请求不执行建表、写索引或自动修复；索引不可用时返回 503。

## 请求边界

`indexed_archive.py` 在只读事务中先固定快照、scope、purpose 和当前限制版本，再执行搜索、阅读、图谱、人物和关系读取。来源用途与撤下状态实时参与过滤，旧快照也会接受当前限制。游标包含快照内容哈希和限制版本，限制变化后旧游标返回过期错误。

这里的“当前限制”以请求已经固定的读事务为准：默认 DELETE 日志模式下，写提交等待旧读事务结束；WAL 模式下，撤下或权限收紧可先提交，新请求使用新限制，已固定旧事务的在途请求仍完整返回旧状态。后来的提交不会取消在途响应，也不能收回客户端已有副本。回滚的限制不改变后续查询或使旧游标过期。可重复演练见 `scripts/check_live_restrictions.py`。

正文阅读使用 `/api/read` 分页，每页最多 50 段。图谱先分页人物和关系标识，再补当前页的证据文本；没有完整证据组的关系不会出现在结果中。范围外、用途不允许或已撤下的内容不会因为定位或翻页自动扩大。

搜索缓存未命中时，先从规范化正文的三元片段倒排中选择最稀疏的候选集合；候选不足或未知时才回退完整扫描，再用原有 `instr` 精确复核。候选结果始终重新经过 scope、用途、撤下、条目和说话人过滤。全量扫描路径直接在 SQL 内汇总命中的 ID 和位置，不再为所有可见段落物化命中标记并按说话人分组；筛选项计数独立复用已有可见范围缓存，绑定快照、scope、purpose 与限制版本，始终统计全部可见段落。候选路径继续只读取精确命中的 ID 和位置，避免临时复制长正文。字面匹配仍保持大小写、NFKC、空白处理和关键词 AND 语义；过短或过于常见的词继续完整扫描。命中结果缓存沿用快照、范围、用途、限制版本和查询参数边界。

含逆序连接的快照在连接稀疏时只对当前可见连接两端的节点进行拓扑排序；连接密集时使用完整可见拓扑序列。检查连接端点是否可见、读取其位置时，以候选 ID 为外层逐个查询，避免 SQLite 为稀疏连接扫描整个段落集合。连接节点的排序键为其遍历过程中的最大原始位置与遍历序号；独立节点沿原始位置索引读取。搜索用这套顺序排列扫描得到的命中 ID，分页后只读取当前页正文；阅读和条目分页可取独立节点的一小段，再与连接节点合并。不能先过滤关键词再对命中子图排序，否则可能改变对白顺序；也不能直接过滤全库的固定拓扑名次，否则撤下或范围变化后顺序可能错误。

在稀疏连接的阅读或条目分页中，若当前页偏移为 O、页大小为 L、命中的连接节点数为 M，独立序列从 `max(0, O-M)` 开始读取至多 `L+M` 项，合并后截取目标页。被省略的独立前缀必在目标页之前，因此深分页不会漏项或重复。AI 小邻域不超过 20 段时只按 ID 读取所需段落。`/api/view` 和素材包重新核验仍使用完整快照路径。

普通 SQL 修改正文、候选片段或索引会通过触发器将索引标为未就绪；候选结构属于 query index version 2，升级和重建只由显式维护事务执行；来源权限只允许收紧，撤下不可撤销。拥有移除触发器或直接改写数据库文件能力的管理员不在这个只读接口边界内，仍需使用维护校验和可信备份。重建前会完整校验原始快照；重建不能修复损坏的原始正文。

## 当前性能结论

2026-10-13 搜索专项优化后，十万段落十并发复测中，搜索 P95 为 0.5097 秒，图谱为 0.2788 秒，AI 段落为 0.0718 秒；搜索和图谱达到本机合成基准的 1 秒目标。原始数据见 `docs/evaluations/t09/benchmark-search-optimized-100k.json`，此前索引版结果继续保留。

缓存未命中时，过短或过于常见的词仍需扫描；可用三元候选索引时只复核候选集合。阅读或条目深分页可能仍需跳过独立序列前缀；如果绝大多数段落互有连接，连接节点集也可能很大。这次基准包含大量独立短段落和小型关系星图，不能替代真实长文本、密集对话、跨设备或生产网络验证。

同日新增的扩展负载验证曾发现上述限制：十万段、每个追加段落 1024 字时，四种搜索场景 P95 为 9.6880–11.6570 秒，深处段落定位为 19.9541 秒。优化前的原始结果仍保留在性能边界报告中，不能与优化后结果混写。密集对白连接、深分页、组合负载和查询期间限制变更的完整数据见 [性能边界报告](performance-boundaries.md)。

2026-10-13 的优化复测加入由读事务固定边界的跨请求可见拓扑缓存、命中 ID 缓存、阅读页缓存和密集连接的一次性全量拓扑序列。缓存键绑定快照内容、范围、用途和限制版本；独立预热后，十万密集连接搜索 P95 降至 0.0477–0.0752 秒，深阅读降至 0.0303 秒；十万长文本搜索降至 0.0502–0.0730 秒，深阅读已降至 0.3183 秒。首次长文本高命中 / 低命中 / 零命中搜索分别为 12.3307 / 8.9966 / 1.3192 秒，缓存未命中的扫描成本仍然明显。优化结果与原始失败边界并存，详见性能边界报告。

同日完成缓存未命中路径的单次正文扫描、SQLite 内精简汇总和候选三元片段倒排；拓扑查询不再强制物化整段正文。十万长文本首次高命中 / 低命中 / 零命中搜索降至 1.2805 / 0.4313 / 0.4459 秒。新增未命中矩阵中，八条查询顺序轮换 P95 为 0.0172 秒，逐次撤下后的查询为 0.7409 秒；十并发全新查询降至 4.8050 秒。全部 90 次请求确认未命中且通过 oracle；原有四类矩阵也重跑通过。详见 [本轮扫描验证](performance-boundaries.md#缓存未命中扫描优化2026-10-13)。

## 高命中冷查询的方案选择（2026-10-13）

新增 `benchmark_search_plans.py` 拆分候选计划、匹配 SQL、拓扑 SQL、Python 排序以及页面 / 元数据读取。优化前，首条十万长文本高命中查询约 1.1199 秒，其中匹配和分组 SQL 约 0.8338 秒、拓扑 SQL 约 0.2008 秒、排序约 0.0562 秒。剖析有额外开销，且 SQL 时间包含权限筛选和结果汇总，不能当作纯 `instr` 用时或 HTTP P95。

在独立内存库中，对相同的 10,011 段规范化文本比较当前三元 posting 与 FTS5 `trigram case_sensitive 1`。高命中词仍返回 9,983 个候选，末尾词精确复核约 0.0287 秒，直接扫描约 0.0276 秒；低命中词两者均缩小到 100 个候选，复核约 0.0003–0.0004 秒。FTS5 没有解决此负载中高命中词候选接近全库的问题。少于三个码点、空词及含 NUL 的查询需要回退，用户引号也必须转义。实验同时核对全角、组合字符、emoji、大小写、字面 `%` / `_` 和关键词 AND。

因此本轮保留原倒排、原 `instr` 与 query index version 2，实施减少临时汇总、复用筛选项计数和按连接候选读取的优化，不新增 FTS 表或迁移。方案实验见 `docs/evaluations/t09/search-plans-before-100k.json` 与 `search-plans-after-100k.json`；端到端结果见性能边界报告。
