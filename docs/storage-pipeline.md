# T04 本地存储与导入链路

日期：2026-10-12。状态：合成数据的导入、持久化、快照定位与网页读取闭环完成；真实数据准入和 M0 仍未通过。

## 1. 当前链路

```text
原创 JSON → 完整结构校验 → BEGIN IMMEDIATE → 快照 / 记录 / 当前策略 → COMMIT
                                                                   ↓
网页 → GET /api/view（范围、用途、可选快照）→ SQLite 只读事务 → 完整性校验 → project()
```

`scripts/archive_store.py` 提供存储读写，`scripts/import_sample.py` 是导入入口。网页不再逐次读取原始 JSON；仍复用 `validate_sample.py` 的字段校验和投影规则。只接受 `synthetic` 输入，不新增真实采集器或外部 AI 连接。

## 2. 运行和导入

Python 3.10+，无第三方运行依赖。在项目根目录执行：

```bash
python3 scripts/import_sample.py
python3 scripts/serve_prototype.py
```

默认数据库为 `data/local/archive.sqlite3`。第一次导入自动激活快照；重复导入相同内容返回 `status: unchanged`，不增加记录。浏览器打开 `http://127.0.0.1:4173`。

兼容原来的一步启动：不传 `--database` 且默认数据库不存在时，服务只在首次启动导入仓库内的合成样本。已有数据库不会被重建或重新灌入 JSON；空库、损坏库、不兼容版本均明确报错，不覆盖修复。

导入自己准备的**合成**新版本：

```bash
python3 scripts/import_sample.py /path/to/synthetic-v2.json --database data/local/archive.sqlite3
python3 scripts/import_sample.py /path/to/synthetic-v2.json --database data/local/archive.sqlite3 --activate
```

首条把新内容存入数据库，不自动切换已存在的活动快照；第二条显式激活它。也可重新导入原始未修改文件并带 `--activate`，切回已经存在的旧快照。新版本须使用新的顶层和记录级 `snapshot_id`，不能只改顶层。

使用独立数据库：

```bash
python3 scripts/import_sample.py --database /tmp/archive-demo.sqlite3
python3 scripts/serve_prototype.py --database /tmp/archive-demo.sqlite3 --port 4174
```

显式 `--database` 必须已成功导入；不存在时不会自动创建。导入成功退出码 0，输出状态、内容哈希、快照、活动快照、数量和本地路径；失败退出码 1，在标准错误输出 JSON 错误。

默认本地目录、`.sqlite3` 文件及其伴随文件已加入 Git 忽略。测试用数据库和实际存储内容均不提交，仓库保留原始合成样本作为可重建输入。使用自定义文件名或路径时仍需自行确保不误提交私密数据。

## 3. 存储结构

数据库结构版本为 `PRAGMA user_version = 1`，与输入契约 `schema_version: "0.1"` 不同。

| 表 | 用途与约束 |
| --- | --- |
| `snapshots` | 快照 ID、规范化内容 SHA-256、顶层元信息、导入时间；相同 ID 不可写入不同内容 |
| `identities` | 跨快照稳定 ID 及记录集合；同一个 ID 不能从人物改成条目等其他类型 |
| `records` | 以快照 + ID 为主键；保留集合内位置和完整 JSON 字段；同一快照同一集合位置唯一 |
| `source_policies` | 跨快照的来源用途限制，独立于不可变快照保存，只收紧、不自动放宽 |
| `withdrawals` | 跨快照撤下 ID 及首次记录的快照；外键指向已知身份和快照 |
| `archive_state` | 单行活动快照指针，外键指向已存在快照 |

这是保留 v0.1 字段的最小关系存储，不是假称已经全面规范化的搜索数据库。来源用途、分支、连接和证据组仍在记录 JSON 中，通过既有校验器核验引用关系；数据库外键约束快照、身份和全局状态。没有正式全文索引或大规模查询优化。

## 4. 原子性、幂等与失败处理

1. 输入先经过 JSON 解析与完整契约校验；重复对象键、非有限数字、混合快照、重复 ID、悬空证据、未知撤下项或不允许存储的来源直接失败。
2. 用排序对象键后的规范 JSON 计算哈希；仅调整对象键顺序不视为新内容，数组顺序保留，不能随意重排段落出处位置。
3. 开启 `BEGIN IMMEDIATE`，建表、快照写入、身份 / 记录写入、用途收紧、撤下记录和活动指针更新均在同一事务内完成。
4. 相同快照 ID + 相同哈希为幂等导入；相同 ID + 不同哈希拒绝，不覆盖旧引用。同内容重复导入还会校验已经存储的快照，不把损坏库伪装成成功。
5. 任一步失败执行回滚，已发布快照不变，不留下部分记录。若这是新文件的首次 SQL 写入失败，可能留下空数据库文件；不会声称它已可读，需人工检查后处理。
6. SQLite 写锁串行化导入，连接超时为 5 秒；锁超时失败交由操作者重试，没有后台无限重试。每个 HTTP 请求独立打开只读连接和读取事务，避免跨线程共享连接。

读取时恢复原始字段与顺序、运行结构校验并核对快照哈希，然后叠加当前策略。损坏时返回失败，不回退到旧 JSON 或其他快照。完整性检查不是数字签名，不能防止能任意改写整个数据库的本机攻击者。

## 5. 旧快照不能绕过限制

- 新导入批次里的 `withdrawn_ids` 合并到全局撤下表；切回旧快照或重复导入旧文件不会解除撤下。
- 对同一来源 ID，各用途按所有已导入策略取更严格值：`denied` 优先于 `unknown`，再优先于 `allowed`。旧快照引用也会使用收紧后的策略。
- **策略收紧与撤下在成功导入时立即生效，即使新内容尚未激活。** 这是本地原型的保守规则；导入测试限制前应使用独立数据库，避免误伤本机其他快照。
- 限制解除、授权到期、审批撤销和人工恢复流程尚未实现，不能通过删除新快照、改旧 JSON 或切换活动快照来模拟恢复。
- 撤下仅阻止服务投影与再次导出，不代表数据库物理擦除，也不能撤回用户已下载的文件。正式删除和隐私处置仍需后续设计。

人物、条目、来源与关系被撤下后的级联可见性，以及不完整证据组的过滤，继续使用统一的 `project()`，不在页面绕过。

## 6. 固定快照链接

```text
GET /api/view?scope=opening&purpose=display&snapshot=fixture-2026-10-10-v1
#/read?passage=passage%3A03&snapshot=fixture-2026-10-10-v1
```

`snapshot` 可省略，省略时读取活动快照；显式传入必须是一个非空值。未知快照返回 404，空值 / 重复参数返回 400，存储不可用返回 503；不把旧标识静默解释成当前版本。

页面首次加载成功后把实际快照写入 URL。检索结果、对话后续、关系证据和导航都保留该快照，刷新与跨页不会悄悄转向新内容。顶部显示 SQLite 存储与固定快照，只有点击“读取当前发布快照”才主动重新读取活动指针。

引用复制再次校验同一个快照的当前导出用途和撤下状态，同时写入带快照的本机段落链接。链接不携带或扩大阅读范围，接收者仍需明确选择后续内容；它也不是公网分享链接或完整关系图布局分享。
