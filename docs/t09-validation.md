# T09 备份恢复、索引优化与规模基线

日期：2026-10-12；索引复测更新：2026-10-13。所有数据都是明确标注的原创合成负载；本记录不代表真实来源准入、公开 V1 或生产灾备验收。

## 备份、恢复与回滚

新增 `scripts/maintain_archive.py`：

- `verify` 使用 SQLite 完整性检查、外键检查、快照哈希、记录顺序、当前来源策略和撤下集合核验；也支持私有反馈收件箱的内容哈希核验。
- `backup` 使用 SQLite 在线备份 API，先在临时目录完成校验，再以不覆盖方式发布到新路径；拒绝已有文件、符号链接和残留 sidecar。
- `restore` 要求备份 SHA-256 和当前可信数据库，合并较新的撤下 / 用途限制；同一快照 ID 内容冲突、旧备份缺少受限身份或来源时停止，不恢复成更宽权限。恢复写入审计事件。
- `activate` 只切换活动快照，要求操作者给出期望当前版本和原因；限制集合不随回滚放宽，变更写入审计事件。

实际演练见 `evaluations/t09/recovery-drill.json`：备份、加入撤下和 external_ai 限制、回滚、恢复到新库、重启 HTTP 服务均成功；恢复后的 `passage:03`、`passage:31` 和师徒关系仍隐藏，`passage:04` 可读取。WAL 提交状态、私有反馈库、损坏库、错误哈希、半成品和故障导入也有自动化覆盖。

新增 16 项维护测试，连同既有 48 项共 64 项自动化检查通过；命令为 `python3 -m unittest discover -s scripts -p 'test_*.py'`。样本契约、Python 编译检查和 Git 差异空白检查通过。实际日常库和 4175 服务没有切换到测试数据。

## 十万段落本机基线

命令：

```bash
python3 scripts/benchmark_archive.py --passages 100000 --concurrency 10 --requests 30 --output docs/evaluations/t09/benchmark-100k.json
```

环境为 Apple M1、8 个逻辑 CPU、8 GiB 内存、Python 3.13.3、SQLite 3.49.2；本机回环 HTTP，服务和客户端在同一进程。导入约 1.79 秒，数据库约 57.86 MiB，峰值 RSS 约 1.73 GiB。首次搜索约 2.38 秒，未清空操作系统磁盘缓存，不能称为冷磁盘测试。

预热后十并发、每场景 30 请求：

| 场景 | 错误 | P50 | P95 | 目标 |
| --- | ---: | ---: | ---: | --- |
| `/api/search` 搜索 | 0 | 38.17 s | 57.19 s | 未达到 ≤1 s |
| 图谱查询 | 0 | 39.21 s | 60.65 s | 未达到 ≤1 s |
| `get_passage` AI 读取 | 0 | 43.90 s | 60.52 s | 未设固定目标，需优化 |

并发期间重复导入返回 `unchanged`，查询仍成功；范围、快照和响应上限断言全部通过。旧路径每次请求重建、完整校验并投影 SQLite 快照，因此十万段落基线明确失败。

每组先独立预热一次，30 次样本的 nearest-rank P95 为第 29 个排序值，样本量较小。搜索轮流使用高命中、低命中和零命中查询；生成器沿用原样本边界，100000 段中 opening 可见 99985 段。图谱为原样本加 60 个合成人物的星状负载，返回页限额仍为 50 人物 / 100 关系。压测专用监听队列为 64，避免默认小队列把连接等待混入查询瓶颈。AI 读取直接测 HTTP，超时设为 120 秒；Skill 客户端实际为 10 秒，在该负载下会失败，不能把长时间最终成功当作客户端可用。短文本、同进程客户端和本机环境不代表真实文本、生产网络或浏览器可交互时间。

## 索引优化后的复测

新增 `scripts/query_index.py` 和 `scripts/indexed_archive.py`。导入或显式维护时建立 `query_records`、`query_links`、`query_evidence` 索引；查询在一个只读事务内按快照、范围、用途和当前撤下 / 权限状态过滤，再按页读取正文。查询请求不会隐式写入或重建索引；索引缺失、版本不符或内容哈希不符时返回暂不可用，要求维护者显式准备。游标同时绑定快照内容哈希和限制版本，限制收紧会使旧游标失效。关系只有完整证据组仍可见。

复测命令：

```bash
python3 scripts/benchmark_archive.py --passages 100000 --concurrency 10 --requests 30 --output docs/evaluations/t09/benchmark-indexed-final-100k.json
```

同一机器、同一合成负载、同一十并发配置的结果：

| 场景 | 旧 P95 | 索引版 P95 | 目标 |
| --- | ---: | ---: | --- |
| `/api/search` 搜索 | 57.1862 s | 24.7118 s | ≤ 1 s，未达到 |
| 图谱查询 | 60.6481 s | 0.2212 s | ≤ 1 s，达到 |
| `get_passage` AI 读取 | 60.5249 s | 0.055 s | 本场景低于客户端 10 s 超时 |

索引版不再为这些接口重建完整 JSON 快照。图谱达到目标；AI 小邻域在未触及 20 段上限时不再读取全库拓扑，P95 降至 0.055 秒。搜索仍扫描规范化文本、计算可见数量；存在逆序连接时还会读取所有可见段落的 ID / 连接来恢复严格顺序，后续应重点分析这条路径，不能宣称整体性能验收通过。最终报告见 [`benchmark-indexed-final-100k.json`](evaluations/t09/benchmark-indexed-final-100k.json)，初版索引报告见 [`benchmark-indexed-100k.json`](evaluations/t09/benchmark-indexed-100k.json)，旧失败基线见 [`benchmark-100k.json`](evaluations/t09/benchmark-100k.json)。初版搜索 P95 17.8653 秒、最终版 24.7118 秒，说明这个短本机基线存在明显尾延迟波动；不能把单次测量当作稳定容量承诺。

最终版三组各 30 请求均无错误。导入含索引约 5.33 秒，数据库约 105.16 MiB，进程峰值 RSS 约 503.81 MiB；首次搜索约 0.90 秒。并发幂等导入返回 `unchanged`，同期开启的搜索约 2.90 秒。较旧基线增加索引存储，减少请求侧全量对象内存。

本轮新增 9 项索引测试和 1 项阅读 HTTP 测试，连同原有 64 项共 74 项通过，覆盖范围 / 用途差分对照、关系证据一致性、50 段分页、目标定位、游标签名和边界、限制收紧、索引损坏拒绝与显式重建、旧库迁移以及只读请求不写库。Python 编译、样本契约、JavaScript 语法和差异空白检查通过。浏览器已验证搜索翻页、段落回链、阅读控件；手机宽度下实际布局宽度和滚动宽度均为 375 px，无横向溢出，控制台未记录错误。超过 50 段的阅读翻页由隔离扩展样本的 HTTP 测试覆盖，日常库保持原有合成样本。

操作步骤见 [恢复手册](recovery-runbook.md)。当前检查仍只覆盖本机合成恢复、索引和基准测量，没有进行真实资料导入、独立生产环境压测或真实移动设备测试。

## 搜索扫描与排序专项优化（2026-10-13）

上一轮索引版搜索 P95 24.7118 秒仍未达标。本轮保留相同数据生成器、查询语义和边界，做了三项调整：

- 将当前允许的来源、条目、人物在 SQL 内预计算，省去每段相同的关联权限检查。
- 一次扫描同时产生命中数和说话人统计；无结果时跳过取页。
- 只排序有可见连接的节点，把它们与按原始位置索引读取的独立段落合并取页；确定当前页 ID 后才取正文，避免对十万个 ID 做 Python 堆排序、JSON 回传和全文载入。

单请求剖析中，旧路径约 0.98 秒、200445 次函数调用，其中全量 ID 排序约 0.35 秒；新路径约 0.19 秒、614 次调用，取页约 0.003 秒。基准 opening 范围有 99985 段，但只有 17 个节点参与连接排序。`EXPLAIN QUERY PLAN` 确认独立段落分页使用 `query_collection` 原始位置索引，不为 `ORDER BY` 建临时排序树。单请求剖析只用于定位，不替代以下端到端 HTTP 延迟。

```bash
python3 scripts/benchmark_archive.py --passages 100000 --concurrency 10 --requests 30 --output docs/evaluations/t09/benchmark-search-optimized-100k.json
```

| 场景 | 上轮索引版 P95 | 本轮 P50 | 本轮 P95 | 错误 |
| --- | ---: | ---: | ---: | ---: |
| 搜索 | 24.7118 s | 0.3783 s | 0.5097 s | 0 / 30 |
| 图谱 | 0.2212 s | 0.2298 s | 0.2788 s | 0 / 30 |
| AI 段落 | 0.0550 s | 0.0561 s | 0.0718 s | 0 / 30 |

搜索细分各 10 请求：高命中 P95 0.5197 秒、低命中 0.5053 秒、零命中 0.4775 秒；首次请求 0.0902 秒。基准现在同时核对准确命中总数和首页段落 ID 顺序，并保存每条样本的查询类型。并发幂等导入返回 `unchanged`，同时查询约 0.6031 秒。详见 [`benchmark-search-optimized-100k.json`](evaluations/t09/benchmark-search-optimized-100k.json)。

新增三项差分回归后，共 77 项 Python 测试通过。固定种子的随机 DAG 混合逆序边、汇合、独立段落、隐藏前驱和撤下，逐页对照原始完整投影算法，检查排序无重复或缺失；另覆盖 Unicode / 全角 / 空白 / 字面符号 / 大小写 / 关键词 AND / 说话人筛选，以及撤下后的游标失效、统计和筛选数量。编译、样本校验、前端语法和差异检查通过。

搜索与图谱通过这一次本机合成基准的 P95 ≤1 秒目标。测试文本短、绝大部分段落独立，不代表真实长文本或密集连接的性能；字面匹配仍扫描索引，深页仍有 OFFSET 成本，该次测量时尚未建立 FTS 或跨请求结果缓存；后续缓存复测见下文。真实来源准入、真实剧情和公开 V1 仍未完成。

## 扩展性能与并发限制边界（2026-10-13）

本轮新增 `scripts/benchmark_boundaries.py`、`scripts/check_live_restrictions.py` 和四项边界回归，完整结果见 [`performance-boundaries.md`](performance-boundaries.md)。所有长文本、密集连接、深分页和组合场景均完成正文、顺序、数量、可见连接、游标和目标校验，未出现正确性错误；但十万长文本搜索 P95 为 9.6880–11.6570 秒，密集连接搜索 P95 为 1.7134–55.3692 秒，密集连接深处阅读 P95 为 90.0337 秒。纯深分页的深搜索 P95 为 1.3014 秒，说明目标深页响应也超过一秒目标；图谱和 AI 局部邻域在扩展负载中仍约 0.27–0.31 秒和 0.05–0.06 秒。20,000 段组合负载仅用于控制本机内存。

独立 300 段库上的 16 个限制变更场景全部通过：DELETE 等待固定读事务，WAL 允许新请求先看到提交后的边界但保持在途旧事务一致，权限收紧只影响指定用途，回滚不使旧游标失效。该语义不会取消客户端已经收到的响应。短独立段落基准仍保留为搜索 P95 0.5097 秒、图谱 0.2788 秒、AI 0.0718 秒；后续优化复测中，扩展负载搜索、密集连接阅读和十万长文本深阅读的预热后 P95 均低于一秒，详见优化复测结果。

新增四项回归后共 81 项 Python 测试通过；编译、样本契约、JavaScript 语法和差异检查通过。后续缓存优化与最终复测见下文；同时推进真实来源准入、解析器版本留档和真实样本质量报告。短独立段落达标不自动通过公开发布验收。

## 缓存优化最终复测（2026-10-13）

四类负载共 840 次预热后计时请求及 28 次首次请求均无错误，oracle 全部通过。十万长文本搜索预热后 P95 为 0.0502–0.0730 秒，深处阅读为 0.3183 秒；密集连接搜索为 0.0477–0.0752 秒、深阅读为 0.0303 秒；深分页搜索为 0.0462–0.0692 秒、深阅读为 0.3378 秒；两万组合搜索为 0.0468–0.0735 秒、深阅读为 0.0305 秒。完整报告和方法见 [性能边界报告](performance-boundaries.md)。

以上计时使用重复查询；长文本首次高命中、低命中和零命中搜索仍分别为 12.3307、8.9966 和 1.3192 秒。首次请求不计入上述 P95，深搜索已复用首页查询缓存，操作系统磁盘缓存未清空。下一步重点验证新查询、缓存淘汰与限制更新后的扫描成本，不能用预热结果代替完整性能或生产验收。

新增两项阅读缓存回归验证跨快照 / scope / 用途隔离，以及权限收紧和撤下后的旧游标失效、正文、总数及旧快照刷新；随机 DAG 回归同时核对稀疏连接阅读分页与深处目标定位。全量 83 项测试通过，Python 编译、样本契约、JavaScript 语法和 Git 差异检查通过。

## 缓存未命中正文扫描（2026-10-13）

未命中路径将全文条件计算、数量和命中标识合并到一次扫描，在 SQLite 内汇总精简中间结果，避免全文临时复制和并发逐行 Python 转换。四类矩阵的 840 次预热后请求与 28 次首次请求均通过 oracle。十万长文本首次高命中 / 低命中 / 零命中分别降至 1.2805 / 0.4313 / 0.4459 秒；原先分别为 12.3307 / 8.9966 / 1.3192 秒。

`benchmark_search_misses.py` 新增十并发全新查询、顺序八条查询轮换、逐次撤下后的重新查询，各 30 次，直接记录缓存读取结果且不清空缓存。90 次请求全部未命中，正文、顺序、数量、统计和筛选项全部正确。P95 分别为 6.2215 / 0.5247 / 0.7776 秒，十并发全新查询仍未达到一秒目标。数据准备及限制写入不计时，未清空磁盘缓存；仅为合成工程验证。

新增矩阵回归与多说话人无连接排序回归后全量 85 项测试通过，包括原有字面匹配、Unicode、关键词 AND、稀疏拓扑、阅读缓存、旧快照及 DELETE/WAL 限制更新回归。编译、样本契约、JavaScript 语法和差异检查通过。最新完整数据与复现命令见 [性能边界报告](performance-boundaries.md)。
